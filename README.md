## Идея решения

Задача решается как бинарная классификация на уровне cookie. Для каждой cookie используются только события, доступные к окончанию её окна наблюдения:

`window_start_ts <= event_ts < window_end_ts`

Это исключает look-ahead leakage: события после `window_end_ts` в признаки не попадают.

Из истории событий строятся агрегированные поведенческие признаки. Основные группы:

- объём и разнообразие событий;
- количества, доли и наличие отдельных `event_name`;
- интервалы между событиями и burst-признаки;
- временные паттерны и активные часы;
- последовательности и переходы между типами событий;
- нормализованная платформа;
- семейство браузера/клиента и ОС, извлечённые из User-Agent;
- разнообразие объявлений, категорий, локаций, продавцов и поисковых запросов;
- статистики `search_page` и последовательных переходов по страницам;
- наличие, разнообразие и движение координат указателя;
- доли точных дубликатов, повторов ключей и событий с одинаковым timestamp;
- поведенческие отношения: search/item, human-action/scrape-action и другие;
- возраст cookie и метаданные создания.

Модель — ансамбль из трёх `CatBoostClassifier` с одинаковыми гиперпараметрами и фиксированными `random_seed` 17, 42 и 2026. Финальный `score` — среднее трёх вероятностей положительного класса.

CatBoost — open-source библиотека градиентного бустинга. В решении также используются NumPy и pandas. Внешние API, большие языковые модели, ручная разметка test и попытки восстановить скрытые ответы в коде решения не используются.

## Опробовано

1. **Quickstart baseline:** `RandomForestClassifier` только на двух признаках — `n_events` и `item_nunique`.
2. **Улучшенное решение:** расширенный feature engineering по истории событий + CatBoost.
3. **Стабилизация:** усреднение трёх CatBoost-моделей с разными фиксированными seed.

Baseline нужен не только как точка отсчёта, но и для проверки, что улучшение связано с содержательными поведенческими признаками.

## Валидация

Так как test расположен позже train по времени, используется временная, а не случайная валидация.

Основной split:

- train: окна с `window_start_ts < 2026-04-17`;
- validation: окна с `window_start_ts >= 2026-04-17` (17–19 апреля 2026 в train-файле).

Основная метрика берётся напрямую из предоставленного организаторами `metric.py`:
максимальный Precision среди порогов, где Recall >= 0.70. Файл `metric.py` в комплекте не изменён.

Результаты на основном временном split:

- quickstart baseline: **P@R>=0.70 = 0.10247**;
- финальный CatBoost ensemble: **P@R>=0.70 = 0.83088**.

Дополнительные временные проверки финального подхода:

- 11–13 апреля: **0.75269**;
- 14–16 апреля: **0.80117**;
- 17–19 апреля: **0.83088**.

Дополнительно для диагностики на основном split:

- PR-AUC = **0.80324**;
- ROC-AUC = **0.93740**.

Итоговая метрика соревнования при этом остаётся только P@R>=0.70.

## Работа с данными

- события фильтруются по индивидуальным временным окнам до построения признаков;
- пропуски трактуются как отдельный источник информации: для полей считаются доли пропусков, а категориальные моды получают значение `__MISSING__`;
- варианты написания платформ нормализуются (`WEB/Web/web`, `ANDROID/...`, `iphone -> ios`);
- дубликаты не удаляются безусловно: вместо этого из них строятся отдельные признаки, поскольку повторяемость сама может характеризовать поведение;
- категориальные признаки передаются CatBoost напрямую либо преобразуются в осмысленные агрегаты.

## Воспроизводимость

Установка зависимостей:

```bash
pip install -r requirements.txt
```

Положить исходные файлы задания в каталог `data/` рядом со скриптом:

```text
data/train.csv
data/test.csv
data/events.csv.gz
```

Запуск:

```bash
python train_solution.py
```

Скрипт заново строит признаки, считает временную validation-метрику, обучает ансамбль на полном train и создаёт `submission.csv`.

Все источники случайности модели зафиксированы через `random_seed`. При экспорте итоговый score округляется до 12 знаков: это устраняет незначимые различия порядка `1e-16` между повторными CPU-запусками и не меняет порядок объектов в текущем submission.
